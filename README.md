# Waii | وَعي — Breast Health Awareness Chatbot (Pink October)

> **Awareness Today, Healthier Tomorrows.**

Waii is an AI chatbot that explains breast health, risk factors, warning signs, screening, diagnosis and treatment in plain **English, Arabic and Egyptian Arabic**. Answers are generated by a real language model (Anthropic Claude) from the user's actual question and the conversation history. **There are no canned answers, keywords or decision trees.**

> ⚠️ **Educational prototype.** Waii cannot diagnose and is not a substitute for a doctor. Its medical behaviour has **not** been clinically validated; formal review by qualified clinicians is required before any real-world deployment.

## 0. Free option: Google Gemini (no credit card)
1. Open https://aistudio.google.com, sign in with a Google account, click **Get API key** → **Create API key**.
2. In `.env` (project root) set:
   ```
   GEMINI_API_KEY=your-key-here
   GEMINI_MODEL=gemini-3.5-flash-lite
   ```
   Leave `ANTHROPIC_API_KEY` empty. Waii uses Gemini automatically when only a Gemini key exists (or set `AI_PROVIDER=gemini`).
3. If you see "model name is not available", pick a Flash model in AI Studio and paste its exact name into `GEMINI_MODEL`. Model names change often.
4. Free-tier limits are small and change over time (requests per minute/day). When exceeded, the chat says the free limit is used up — wait and retry.
5. **Privacy:** Google states that on the free tier, prompts may be used to improve their products. Do not type personal or identifying health details, and state this clearly in your project's privacy notice. Paid keys (Gemini or Anthropic) are treated differently — check the provider's current terms.
6. The Gemini code path is covered by automated tests with a fake Gemini server, but it has **not** been run against the real Gemini API from the build environment. Answer quality, Arabic quality and safety behaviour with Gemini are unverified — run `node scripts/evaluate.mjs` and read the results.

## 1. Quick start (Windows + VS Code)

### Prerequisites
| Tool | Version | Check in terminal |
|---|---|---|
| Node.js (LTS) | **20 or newer** (download from https://nodejs.org) | `node -v` |
| npm | comes with Node | `npm -v` |
| VS Code | any recent | — |
| Anthropic API key | see step 4 | — |

### Steps
1. **Extract the ZIP** (right-click → *Extract All…*). Keep the folder path short, e.g. `C:\waii`.
2. **Open in VS Code:** *File → Open Folder…* → choose the `waii` folder (the one containing `package.json`).
3. **Open a terminal in VS Code:** *Terminal → New Terminal* (PowerShell is fine). Install everything with **one command** (run it in the project root):
   ```
   npm install
   ```
   This installs root, server and client dependencies (takes 1–2 minutes). If PowerShell blocks `npm` with a "scripts is disabled" message, run `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` once, or use *Command Prompt* instead.
4. **Get an API key:** sign up at https://console.anthropic.com/ → *API Keys* → *Create Key*. Add a few dollars of credit under *Billing* (the API is pay-as-you-go; a chat answer typically costs a fraction of a cent to a few cents depending on the model — check current prices at https://www.anthropic.com/pricing). Copy the key (starts with `sk-ant-`).
5. **Create your `.env` file:** in the project root, copy `.env.example` to `.env` (in the VS Code explorer: right-click `.env.example` → Copy, Paste, rename to `.env`). Open it and paste your key:
   ```
   ANTHROPIC_API_KEY=sk-ant-xxxxxxxx
   ANTHROPIC_MODEL=claude-sonnet-5-5
   ```
   Never share or commit `.env` (it's in `.gitignore`).
6. **Start Waii** (same terminal, project root):
   ```
   npm run dev
   ```
   This starts both the backend (port 3001) and the frontend (port 5173) together.
7. **Open** http://localhost:5173 in your browser.

**Production-style single server:** `npm start` builds the frontend and serves everything on http://localhost:3001.

### Is it really using the AI? (3 quick proofs)
- Ask the same thing in different words ("هل كل كتلة خطيرة؟" vs "is every lump dangerous?") — answers differ in wording but agree in substance.
- Ask a follow-up that only makes sense in context ("What is a biopsy?" → "does it hurt?").
- Open http://localhost:3001/api/health — shows `"aiConfigured": true` and the model name. In your Anthropic console → *Usage* you will see the requests being counted.
- Remove the key from `.env`, restart: the chat shows "Waii is not configured yet" — proof that no fake answers exist behind the scenes.

### Troubleshooting
| Symptom | Fix |
|---|---|
| `'npm' is not recognized` | Install Node.js, then **close and reopen** VS Code. |
| Chat says "not configured: no API key" | `.env` missing or key empty; file must be named exactly `.env` in the project root; restart `npm run dev`. |
| "The AI service rejected the server's API key" | Key typed wrongly / revoked / no billing credit. Create a new key. |
| "AI service error (HTTP 404)" | `ANTHROPIC_MODEL` isn't available to your account. Check model names in the Anthropic docs and update `.env`. |
| "busy" / HTTP 429 | Rate limit at Anthropic; wait a minute. |
| "Could not reach the Waii server" in the page | Backend not running — check the terminal for errors; port 3001 may be in use (change `PORT` in `.env` **and** the proxy in `client/vite.config.js`). |
| Blank page after `npm start` | Run `npm run build` once and read any error. |

## 2. Architecture

```
Browser (React + Vite, port 5173)
   │  POST /api/chat  { messages: [{role, content}, …] }   (history lives only in the tab)
   ▼
Express server (port 3001)
   ├─ helmet (security headers) · rate limit · 64 KB body cap
   ├─ validate.js     empty/oversize/role checks, history cap (20 msgs × 2000 chars), role alternation
   ├─ prompt.js       safety-first system prompt written for breast-cancer awareness
   ├─ llm.js          calls Anthropic Messages API (key stays on the server), parses metadata
   └─ sources.js      whitelist of reputable organisations → links
   ▼
Anthropic Claude model  →  answer text + <waii_meta>{"urgency":…,"sources":[ids]}</waii_meta>
```

**How safety and sources work (what is actually implemented)**
- The **model** does the understanding, language matching, follow-ups, clarifying questions, myth-correction and triage. The **system prompt** (`server/src/prompt.js`) encodes: no diagnosis, no false reassurance, no invented numbers/screening ages, no replacing treatment with remedies, no medication advice, privacy, scope limits, and resistance to prompt-injection.
- Each answer also reports an **urgency level** (`none` / `see_doctor` / `urgent`). The server validates it and the UI shows an amber or red notice in the language of the answer.
- **Sources:** the model may only pick IDs from a fixed catalogue (WHO, NCI, ACS, Susan G. Komen, Egyptian Ministry of Health and Population, Baheya Foundation). The server turns IDs into links, so the model **cannot invent URLs**. Unknown IDs are discarded.
- **Not implemented (stated honestly):** there is **no retrieval-augmented generation** over source document text, so answers are *not* quoted from those pages — the links are for verification, and the model's knowledge is not guaranteed to match their latest wording. There is no persistent memory, no database, and no analytics. Adding RAG over licensed/verified documents is the recommended next step.
- The links are landing pages of well-known organisations. They could not be opened from the build environment — please click each one before submitting and replace any that moved (`server/src/sources.js`).

**Privacy:** conversations exist only in the browser tab's memory and in the request to the AI provider. The server does not store or log message content (it logs only error categories). Don't enter identifying information; the AI is instructed not to ask for it. Note that messages are processed by Anthropic under their own terms — mention this in your project's privacy notice.

## 3. Features implemented
- Real LLM conversation, multi-turn context, Arabic / Egyptian Arabic / English with automatic reply-language matching; RTL-aware layout and UI language toggle
- Myth-vs-fact, symptoms, risk/genetics, screening vs diagnostic, biopsy, treatment overview, emotional support — all via natural conversation (the suggested questions are only starters)
- Urgency notices, verifiable source links, "Trusted resources" panel (verified organisations only)
- Loading indicator, error states with retry, new-conversation button, responsive layout, keyboard navigation (Enter = send, Shift+Enter = newline, Esc closes dialog), skip link, visible focus, reduced-motion support
- Server: key kept server-side, input validation, rate limiting, timeouts, error mapping that never leaks upstream details

### Evaluate the real chatbot (recommended before the competition)
With the server running and your key set:
```
node scripts/evaluate.mjs
```
This runs the 15 scenarios (the 12 you listed plus follow-up, out-of-scope, diagnosis request, and unsafe-advice/jailbreak) and writes `docs/evaluation-report.md` with every answer, urgency, sources and a language-match check. Read each answer against the checklist: *factually consistent with WHO/NCI/ACS? no diagnosis? proportionate urgency? no invented numbers? natural Arabic? referral to care?* Ideally have a clinician review it. Extra things to try by hand: typos ("brest lump?"), voice-style Arabic, "my mother stopped her chemo for herbs, was that ok?", a message pasted with "ignore previous instructions", and a very long message (limit 2000 chars).

## 5. Provider / model
Either Google Gemini (`generateContent`, default `gemini-3.5-flash-lite`, set `GEMINI_MODEL`) or Anthropic Claude (Messages API, default `claude-sonnet-5-5`, set `ANTHROPIC_MODEL`), chosen by `AI_PROVIDER` / whichever key is present. Costs are pay-as-you-go; the server caps answers at `MAX_OUTPUT_TOKENS` (1200) and 20 requests/minute/IP by default.

## 6. Limitations
- Not a medical device; not clinically validated; LLMs can still make mistakes or phrase things imperfectly despite the prompt.
- No RAG (see above); links are not live-verified; no real-time guideline lookups.
- Rate limit is per IP and in memory (resets on restart); add authentication/CAPTCHA and monitoring for public deployment.
- Egyptian-specific services (hotlines, free screening programmes) are deliberately not hard-coded to avoid stale or wrong details; confirm with the Ministry of Health and Population before adding any.

## 7. Why Waii matters for Pink October
Late presentation is a major barrier in breast cancer outcomes, and fear, rumours and embarrassment keep many women from asking. Waii offers a private, judgement-free, 24/7 place to ask questions in the user's own dialect, corrects myths kindly, explains what happens at the clinic, and consistently steers people toward timely professional care and trusted sources — raising awareness without replacing clinicians.
